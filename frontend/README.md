# 대소고나 프론트엔드

생활 기록과 중요한 선택을 중심으로 학교생활을 진행합니다. 기존 게임 기획서 v1.2의 `/api/v1`에 생활 기록 조회를 추가했습니다. React와 TypeScript를 사용합니다. Zustand는 화면 상태와 마지막 회차 ID를 관리하고 TanStack Query는 서버 조회·변경과 갱신을 담당합니다.

## 이 저장소에서의 연결 상태

이 폴더는 별도로 개발하던 웹 프로젝트를 가져온 것입니다. 서버 없이 실행하는 데모가 포함되어 있습니다. 기존 `com.silvally` 서버와의 완전한 통합은 별도 작업입니다. API 주소만 바꾸어 모든 기능이 호환된다고 보장하지 않습니다.

웹이 기대하는 응답 구조는 `src/api/contracts.ts`, 호출 목록은 `src/api/hooks.ts`에서 확인할 수 있습니다. 팀 서버와 연결할 때 생활 기록 조회, 학기 집중·방학·나르샤·스트레스 이벤트, `ProgressView`의 필드명과 확장 정보를 대조해야 합니다. 이번 변경은 Java 서버나 DB를 수정하지 않습니다.

아래 명령은 이 `frontend/` 폴더에서 실행합니다. 저장소 루트에서는 먼저 `cd frontend`를 실행합니다.

## 순한맛과 매운맛

코드는 공통으로 유지하고 회차 생성 시 `edition`을 저장합니다. 순한맛(MILD)은 1학년 1학기 희망 직무 안내부터 시작하며 입학·비포스쿨과 자퇴를 제공하지 않습니다. 스트레스는 휴식·상담으로 관리하며 기초 역량·채용 준비 보너스가 있습니다. 매운맛(SPICY)은 기존 입학부터의 진행과 자퇴 확인·기존 채용 규칙을 유지합니다. 기존 회차와 edition 생략 API 요청은 SPICY입니다. 한 회차의 모드는 중간에 바꾸지 않습니다.

시작 화면은 기본적으로 순한맛을 선택하며, 두 버전의 이어하기는 분리됩니다. 이전에 저장한 매운맛 회차는 매운맛을 고른 뒤 이어 할 수 있습니다.

제출/배포 파일은 따로 만듭니다.

```sh
npm run build:mild
npm run build:spicy
```

각각 `dist/mild/`, `dist/spicy/`에 생성됩니다. 각 폴더를 웹 루트로 배포하며 API는 별도로 실행합니다. 순한맛 빌드에는 버전 선택 메뉴가 없고 다른 모드 회차를 열지 않습니다. 두 출력은 동일 소스에서 만들므로 코드 파일을 두 벌로 관리하지 않습니다.

전공역량 강화 캠프는 두 버전 모두 **1·2학년만** 제공합니다. 3학년 여름·겨울에는 캠프를 선택하거나 API로 강제 신청할 수 없습니다. 3학년 취업역량 캠프는 별도 콘텐츠로 유지합니다. 취업 지원 보너스는 게임용 규칙이며 실제 학교 취업률·채용 보장이 아닙니다.

## 1차 배포: Vercel 순한맛

Vercel에서 `shawnatak926/silvally` 저장소를 가져오고 **Root Directory를 `frontend`**로 지정합니다. 이 폴더의 `vercel.json`이 다음 값을 적용합니다.

- Framework: Vite
- Install Command: `npm ci`
- Build Command: `npm run build:mild`
- Output Directory: `dist/mild`
- Node.js: 22.x (이 프로젝트의 최소 버전은 22.12)

Production과 사용할 Preview 환경의 **`VITE_API_BASE_URL`**에 실제 배포한 Spring 서버 주소를 `/api/v1`까지 입력합니다. 예시 형식은 `https://your-api.example/api/v1`이며, 이 예시 도메인을 실제 주소로 사용하지 않습니다. 값 변경 후 다시 빌드·배포해야 합니다. 누락·HTTP·로컬 주소·잘못된 경로는 Vercel 빌드에서 거절합니다. 기존 `DAESOGO_BACKEND_URL`은 Vite 개발 서버용이므로 운영 환경의 API 연결 설정을 대신하지 않습니다.

Vercel은 이 프론트엔드를 배포하며 Spring Boot 서버는 별도로 실행합니다. #32가 반영된 Spring 서버에서는 `CORS_ALLOWED_ORIGINS`에 실제 Vercel 웹 주소(경로·끝 슬래시 제외)를 등록합니다. 해당 설정은 `Content-Type`, `Idempotency-Key`, `X-Expected-Version` 헤더와 GET/POST/PUT/DELETE/OPTIONS 요청을 허용합니다. AI 키는 기존 서버에만 둡니다.

`/play/:id`, `/ending/:id`는 `index.html`로 연결해 직접 접속·새로고침을 처리합니다. `/api`나 PDF·사진 경로를 SPA로 바꾸지 않습니다. 이 설정은 Spring API 프록시가 아니며, 브라우저는 `VITE_API_BASE_URL`로 직접 요청합니다. 실제 서버 주소가 아직 확정되지 않았으므로 특정 서버 URL을 코드에 고정하지 않았습니다.

현재 API 계약 통합은 #32, 모드 저장·순한맛 규칙은 #30, 웹은 이 PR(#29)에 나뉘어 있습니다. 서버에 필요한 변경을 반영하고 API 계약을 맞춘 뒤 배포된 주소에서 회차 생성→희망 직무→턴 진행→새로고침→졸업을 확인해야 합니다. 프론트 빌드 성공만으로 온라인 게임이 완성된 것으로 표시하지 않습니다.

공식 설정 근거: [Vercel의 Vite SPA 안내](https://vercel.com/docs/frameworks/frontend/vite#using-vite-to-make-spas), [vercel.json 설정](https://vercel.com/docs/project-configuration/vercel-json).

## 바로 플레이하기

Node.js 22.12 이상에서 실행합니다.

```sh
npm ci
npm run demo
```

브라우저에서 Vite가 표시한 주소를 엽니다. 휴대전화에서도 열려면 같은 Wi-Fi에서 아래 명령을 실행하고, 터미널에 표시되는 Network 주소에 접속합니다.

```sh
npm run demo -- --host 0.0.0.0
```

데모는 기본 장면과 기본 면접 질문을 표시하고 개발 서버의 메모리에 회차를 저장합니다. 브라우저를 새로고침하면 이어 할 수 있고, 데모 서버를 재시작하면 회차가 초기화됩니다. 데모 채용에는 기획서 v1.2 예시 A의 고정 시드를 사용합니다.

## 학교생활 화면

학교 면접은 질문을 읽고 자유 답변을 제출합니다. 비포스쿨 1일차는 일곱 장소 중 두 곳, 2일차는 여덟 전공 실습 중 두 가지를 고릅니다. 확정하면 두 활동이 인생 기록에 각각 저장됩니다.

학년당 정규 24턴을 1·2학기 12턴씩 진행합니다. 학기 시작에 **이번 학기에 집중할 것**을 고르면 매 정규 턴마다 효과가 적용됩니다. 12턴과 24턴을 마치면 각각 여름방학과 겨울방학을 보냅니다. 1·2학년 전공강화캠프에 참가하면 방학 실습 2턴을 추가로 진행합니다.

**일시 정지**, **1×~16×**, **다음 결정까지**로 시간을 조절합니다. 정규 수업과 가능한 과정·프로젝트 작업은 자동으로 처리됩니다. 중대 결정과 채용 일정에서 시간이 멈추며, 자동 진행 중이었다면 결정 이후 이어집니다. 채용 일정은 **턴 종료**로 직접 넘길 수 있습니다.

선택 이벤트·희망 직무·학기 집중은 입력 없이 10초가 지나면 자동 확정합니다. 남은 시간을 막대로 보여 주며 클릭·키 입력·스크롤은 10초를 다시 시작합니다. 고른 항목이 있으면 그 항목을, 없으면 서버가 허용한 항목 중 하나를 고릅니다. 비포스쿨 복수 선택은 고른 항목을 유지하고 남은 개수만 채웁니다. 자동 선택은 화면에서 끄거나 다시 켤 수 있습니다. 대화창·백그라운드 탭·저장 중·통신 오류에서는 타이머를 멈추고 복귀하면 10초부터 다시 시작합니다. 면접 답변과 졸업 확정은 직접 제출하며, 나르샤 기타 주제는 임의로 만들지 않습니다. 자퇴 관련 항목은 자동 추첨에서 제외하고 재학 유지·휴식·상담만 자동 선택합니다. 결과는 수동 선택과 같은 API·명령 키·버전 처리로 저장합니다.

나르샤는 학년별로 별도 프로젝트를 진행합니다. 1학년은 8턴에 주제를 고르고 23턴에 마무리합니다. 2학년은 2턴에 새 주제와 멘토링 방향을 정하고 22턴에 발표·순위를 확인합니다. 두 학년 모두 **기타 · 직접 주제 입력**에서 2~80자의 주제를 정할 수 있으며, 학년별 프로젝트는 수첩·학교생활 현황·졸업 기록에 각각 표시됩니다. 게임 내 1~3위 팀은 23턴에 소프트웨이브 참가를 선택할 수 있습니다.

희망 직무 선택에는 인공지능 개발자를 포함한 11개 직무 전체를 캐릭터 적합도순으로 표시합니다. 점수·능력치·활동 근거를 참고해 순위와 관계없이 원하는 직무를 선택할 수 있습니다. 동점은 활동 일치 수, 카탈로그 고정 순서로 정렬합니다. 이후 희망 직무 변경의 기존 조건·횟수 제한은 유지합니다. 정규 생활의 기본 성장과 전공·진로 보너스를 줄이고, 양수 기술 성장에는 0.25 배율과 기존 체력·숙련도 보정을 적용합니다. 소수점 성장은 회차에 저장해 다음 턴으로 누적합니다.

학기 목표와 학과·희망 직무로 유지하는 기술을 제외하고, 5·10·15·20턴에 덜 연습한 기술 한 가지가 1~2점 떨어질 수 있습니다. 초보 기술은 이 규칙으로 10점 미만이 되지 않습니다. **생활과 학업의 균형** 목표는 연습 부족에 따른 하락을 막습니다. 턴 시작 시 체력 40 미만 또는 스트레스 65 이상이면 프로그래밍 2점, 학업 1점 하락도 적용됩니다. 감소 이유와 항목은 인생 기록에 저장됩니다. 성적은 시험과 수행평가에서 결정됩니다.

두 버전 모두 스트레스 60 이상이면 휴식·친구와 대화·교사 상담 선택이 열립니다. 매운맛에서 90 이상이면 학교생활을 이어갈 방법과 자퇴 고민을 선택할 수 있습니다. 자퇴를 고민하면 다음 화면에서 재학을 이어가거나 자퇴를 최종 확정합니다. 결정 중에는 시간이 멈추고, 선택과 결과는 인생 기록에 남습니다. 자퇴 엔딩은 당시까지의 학교생활을 정리합니다.

시험 대비·응시와 나르샤 개발·마감이 스트레스를 높입니다. 인생 기록에서 시험과 프로젝트 때문에 쌓인 부담의 원인과 증가량을 볼 수 있습니다. 휴식·상담과 회복을 선택하면 스트레스가 내려갑니다. 일상 사건과 스트레스 대응 선택지는 상황에 맞는 후보에서 추첨되며, 같은 회차의 같은 시기에는 다시 조회해도 유지됩니다.

중앙 화면은 **최근 로그 → 선택지 → 여태껏 했던 로그** 순서입니다. 중대 결정은 최근 로그 아래에 표시되며 필수 선택 중에는 시간이 멈춥니다. 새 로그가 생기면 이전 장면은 아래 기록으로 이동합니다. 데스크톱에는 왼쪽 학생 정보와 오른쪽 학교생활 정보가 나뉘며, 좁은 화면에서는 본문 아래에 이어집니다.

## Spring Boot 연결

```sh
npm run dev
```

호환되는 Spring Boot 서버를 먼저 실행합니다. 개발 서버는 `/api` 요청을 기본적으로 `http://127.0.0.1:8080`으로 전달합니다. 다른 주소는 프로젝트의 `.env.local`에 설정합니다. `.env.example`에는 공개 가능한 주소 예시만 들어 있습니다.

```dotenv
DAESOGO_BACKEND_URL=http://127.0.0.1:8080
```

AI API 키는 서버 환경변수에만 설정합니다. `VITE_` 변수는 브라우저에 공개되므로 키를 넣지 않습니다. 데모는 LLM을 호출하지 않습니다.

빌드 결과는 `dist/`에 생성됩니다. 운영에서는 같은 출처에 SPA와 `/api/v1`을 제공하고 `/play/:id`, `/ending/:id` 직접 접속을 `index.html`로 연결합니다. 별도 API 출처가 필요하면 빌드 시 `VITE_API_BASE_URL`에 `/api/v1`을 포함한 주소를 설정합니다. 데모 미들웨어는 개발 모드에서만 시작됩니다.

- API 타입과 통신은 `src/api/`에 있습니다. 쓰기는 `Idempotency-Key`와 기존 회차의 `X-Expected-Version`을 전송합니다.
- 입학 판정·추천·졸업 결과는 서버 응답을 사용합니다. 결과를 확인할 수 없는 쓰기는 탭에 보관했다가 같은 키로 재전송합니다.
- 학교 사진은 제공된 PNG 원본을 사용합니다. 보조 영역에서 **사진 보기**로 전체 사진을 열 수 있습니다.
- 교표와 탭 아이콘은 대구소프트웨어마이스터고등학교 홈페이지의 공개 이미지를 사용합니다. [학교상징](https://dgsw.dge.hs.kr/dgswh/cm/cntnts/cntntsView.do?mi=10091622&cntntsId=10215454)

## 검증

```sh
npm run build
npm test
```

브라우저 테스트에는 Chrome이 필요합니다. 데모 서버를 별도 포트에 띄워 PC·모바일과 API 재시도 경로를 확인합니다.

호환되는 Spring Boot 테스트 서버에 연결하려면 `DAESOGO_E2E_BACKEND_URL=http://127.0.0.1:8080 npm test`를 사용합니다. 채용 재현을 위해 테스트용 고정 시드를 사용하고, 테스트 서버의 AI는 꺼 둡니다. 일부 화면·오류 재현 테스트는 응답을 테스트 데이터로 대체합니다. 데모 테스트 통과는 팀 서버와의 통합 완료를 뜻하지 않습니다.
