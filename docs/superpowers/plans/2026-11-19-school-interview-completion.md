# Issue 8 학교 면접 완성 계획

**Goal:** PR #16의 공통 면접을 재사용하여 지원 동기·활동 맥락, 근거 기반 평가·최종 판정 저장, 회차 생성부터 결과 확인까지 HTTP 흐름을 보완합니다.
**Base:** main의 댓글은 PR #11 시점이며 공통 면접 구현은 작업 시작 당시 OPEN이던 PR #16에 있습니다(최종 확인 시 MERGED). 원래 작업 폴더의 초기 main 이력은 보존하고 PR #16을 기반으로 별도 브랜치/워크트리에서 진행합니다.
**Constraints:** Spring Boot 4.1.1/Java21/H2/JPA 유지. 기존 DTO 생성자·선택 API·오류 코드·입학 멱등 응답·버전 처리를 유지합니다. 1차144/최종72, 동점자 우선, 기존 보호막 및 최종25/30/20/25 가중치를 변경하지 않습니다.

## 기능 커밋

1. 지원 동기와 활동 기반 질문 보완
   - AD02에 선택적 motivation(공백 아닌1~1200자)을 추가하고 서류 이력에 저장합니다. 기존 요청은 변경 없이 허용합니다.
   - 학교 질문에 저장된 지원 동기와 앞선 활동을 반영하고 MOCK/FALLBACK 모두 같은 맥락을 사용합니다. 기존 질문은 재발급하지 않습니다.
   - HTTP 맥락·새로고침·생성 실패·동시 조회 테스트 및 전체 build 후 커밋.
2. 근거 기반 평가와 최종 판정 저장·조회
   - 반복 키워드 대신 완결된 서술과 구체적 행동/역할/원인/수정/검증/목표 근거로 항목별0~25를 평가합니다. 근거 인용·충족/미충족 설명·루브릭 버전을 저장합니다. AI의 의미 이해 능력으로 표기하지 않습니다.
   - 합격/불합격의 실제 단계 점수·순위·정원·보호막·사유·다음 단계와 평가를 저장하고 AD05 결과 GET을 제공합니다.
   - 합격/불합격·같은 준비에서 답변만 다른 판정·보호막·동점·근거 저장·재시도 테스트 및 build 후 커밋.
3. 전 과정 HTTP 검증과 연동 문서
   - 회차 생성→전형 선택→서류→2차 준비→질문→ANSWER→결과 조회를 실제 Controller/Service/JPA로 검증합니다.
   - 잘못된/다른 회차 질문, 빈/공백/초과 답변, 잘못된 단계, 중복 명령·본문 충돌·버전 충돌과 동시 제출을 검증합니다.
   - 요청/응답 예시·담당 연동·남은 경계를 문서화하고 전체 build 후 커밋.

## 주의할 경계

- 기존 회차에 없는 지원 동기를 추정하여 만들지 않습니다.
- 재시도는 질문 완료/현재 단계 검사보다 먼저 저장 응답을 반환해야 합니다.
- 같은 답변·같은 단계 점수를 일반 기준에 재사용하며 보호막에서 다시 평가/추첨하지 않습니다. 최종 가중치가 전형 공통이므로 최종 보호막 점수도 같습니다.
- 실제 외부 AI 채점은 범위 밖이며 기본 평가의 한계를 명시합니다.
