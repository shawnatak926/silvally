# 학교 사건과 스트레스 API (#23)

이 문서의 턴·확률·능력치·선발 기준은 학교 공식 규정이 아닌 게임 규칙입니다. 실제 안내와 과거 사례·예정·불일치는 출처 카탈로그의 `classification`, `fact`, `notice`로 구분합니다. 2027 자료 제목을 실제 운영 연도로 일반화하지 않습니다.

## 실행과 기존 데이터

Java 21, 기존 `./gradlew bootRun`과 H2/JPA 설정을 그대로 사용합니다. 새 `school_event_draw` 테이블은 회차·시기·발생 종류별 사건 전체와 선택 순서를 저장합니다. 사건 없음도 보존하므로 재조회로 재추첨하지 않습니다. 회차 생성·현재 스트레스·과거 기록을 초기화하는 코드는 없습니다. 기존 서버의 기본 H2 설정 자체는 메모리 DB 및 create-drop이므로 서버 재시작 후 영구 보존을 주장하지 않습니다.

새 학교 사건의 양수 기술 보상은 `silvally.growth.school-event-rate`(기본 0.25)를 적용하고, 회차의 소수점 잔여량을 저장해 누적합니다. 음수 효과·S·H는 배율로 축소하지 않습니다. G(성적)는 직접 변경하지 않습니다. #21 담당 공통 성장 정책이 합쳐질 때 이 지점에 한 번만 연결해야 하며 다른 수업/행동 성장 공식을 이 PR에서 재작성하지 않습니다.

## 사건 목록과 선택

- `GET /api/v1/players/{id}/events`: 기존 사건과 조건부 학교 사건. 조회는 짧게 회차 행을 잠그고 첫 추첨만 저장하며 회차 버전은 올리지 않습니다.
- `GET /api/v1/players/{id}/events/{eventCode}`: 현재 제공되는 무작위 사건의 동일 스냅샷.
- `POST /api/v1/players/{id}/events/{eventCode}/choices`: 기존 `Idempotency-Key`(UUID), `X-Expected-Version`, `{"choiceCode":"..."}` 사용. 임의 선택 코드, 미제공 사건, 반복 수령, 오래된 버전은 거절합니다.
- 새 선택은 AP 0. 같은 종류는 같은 시기에 한 번만 처리하며 60 단계 후 같은 턴 90 단계로 상승하면 별도 위기 사건이 가능합니다. 90 단계 처리 후 60 단계가 추가로 열리지는 않습니다.

`EventView`에 다음 필드를 추가했습니다. 기존 생성자는 유지했습니다.

```json
{
  "code": "STRESS_SUPPORT",
  "required": true,
  "blocksAuto": true,
  "source": null,
  "choices": [{"code":"STRESS_REST","label":"일정을 줄이고 쉬기","apCost":0,"enabled":true,"reason":null,"description":"게임용 선택 효과 안내"}]
}
```

S 60 이상은 휴식·도움 후보를 보장하는 3개 선택, S 90 이상은 도움·휴식·자퇴 고민입니다. 고민 이후에는 `WITHDRAWAL_DECISION`에서 재학 유지/최종 자퇴를 다시 선택합니다. 확정 전에는 끝나지 않습니다. 확정 시 `SCHOOL_WITHDRAWAL` 엔딩에 종료 학년·턴·프로젝트·자격증·최종 능력치·향후 계획을 저장합니다. `GET /ending`으로 조회하며 이후 턴은 거절합니다.

필수 학과·수업·학기·방학·기존 필수 사건의 처리는 유지합니다. 필수 사건 대기는 서버도 턴 진행을 거절합니다. 일반 `DAILY_*` 사건은 `required=false`, `blocksAuto=false`라 지나칠 수 있습니다. 프론트는 자동 진행 의도를 별도 유지하고 필수 사건 완료 후 재개해야 합니다. 이 PR은 서버 구현이며 #26 UI 통합 자체를 완료한 것으로 표시하지 않습니다.

## 부담과 기록

정규 턴을 마칠 때 한 번만 계산합니다. 캠프 추가 실습 턴에는 같은 정규 부담을 재가산하지 않습니다.

- 수업 0~1, 중간 준비 1~2/응시 3~5, 수행 준비 1/제출 3~4, 기말 준비 2~3/응시 4~6
- 진행 중 나르샤 0~1, 마감 2~3
- 위 자동 양수 부하 합계 최대 +5. 강행 선택 등 개별 행동의 S +5를 이 상한으로 차단하지 않습니다.
- H >= 40, 시험·제출(학기 6·10·12턴)·막판 마감이 없는 정규 턴은 자연 회복 -2. 실제 적용 시 0~100으로 제한합니다.

턴/선택 `MutationResult.details.stressLoad`에는 `stressBefore`, `stressAfter`, `total`, `sources[{code,reason,delta}]`를 저장합니다. 음수는 회복입니다. 실제 적용량의 합이 total과 같습니다. 같은 멱등키 재시도는 다시 가산하지 않습니다. #21 시험 엔진은 동일 부담을 중복 가산하지 않아야 합니다.

`GET /history` 항목에는 `evidenceJson`이 추가됩니다. JSON에는 부담 내역, 출처, 장면, 선택과 실제 효과가 들어갑니다. 중요한 시험·마감과 학교 시간 장면은 기존 HistoryService/NarrativeService를 사용합니다. 한 턴에 학교 장면과 시험/마감이 겹치면 하나의 장면으로 합쳐 별도 LLM 요청을 중복 생성하지 않습니다. 같은 요청의 재시도는 기록을 중복 생성하지 않습니다.

## 학교 자료와 다른 담당과의 연결

- `GET /api/v1/catalog/school-life`: playerId 없이 조회 가능한 출처 35개. 각 항목은 `code`, `title`, `url`, `fact`, `classification`, `notice`, 선택적인 `year`/`appliesTo`를 제공합니다.
- `rules/school-content.json`: 학교 선택형 사건 13종과 시간 장면 20개 및 공통 근거. 일반 생활·시험·나르샤 후보도 현재 상태에 따라 추가합니다.
- 자료 소개·온라인 준비 사건은 국내 실습/실리콘밸리 참가, 장비 지급, 자격증 취득, 채용 합격 상태를 생성하지 않습니다.
- 해외 기간 6주/8주 불일치, 증축 입주 예정, 2026 입학생 교육과정 적용 범위를 별도 표기합니다. 비포스쿨 5일/탐색 2곳은 기존 게임 규칙이며 자료로 확인한 운영 규정이라고 쓰지 않습니다.
- PDF 경로 `/school-sources/...`는 #29의 웹 정적 파일에서 제공합니다. Java API가 PDF 파일을 제공하는 것은 아닙니다.
- #28은 이 출처/장면 증거를 AI의 학교 근거 컨텍스트로 확장할 수 있습니다. 기존 AI 호출·실패 대체·스냅샷 구조를 재사용합니다.
- #24 나르샤 도메인 개편과 #25 학과·수업 개편은 이 PR에서 중복 구현하지 않습니다. 현재 서버의 STARTED/RESUMED/WRAPPED/RANKED 상태를 스트레스 계산의 연결 지점으로 사용합니다.

## 검증

`./gradlew build`

경계값 59/60/89/90, 60→90, 휴식·상담 감소, 자퇴 재고/확정, 재조회·동시 조회·버전·멱등, 부하 상한·체력 경계·범위, 128개 시드의 72턴 단순 모델, 13개 선택형 사건·20개 장면과 출처/서사, 나르샤 포함 72정규턴 졸업, 실제 HTTP Controller–Service–JPA 경로를 검증합니다. 단순 모델의 빈도는 모든 실제 플레이를 보장하지 않습니다. 실 LLM 외부 API나 배포 서버의 실행을 이 테스트 통과만으로 주장하지 않습니다.
